# APP Fraud LSTM — Triton Inference Server

Serves the `fraud_detection_unified.onnx` model via [NVIDIA Triton Inference Server](https://docs.nvidia.com/deeplearning/triton-inference-server/user-guide/docs/index.html) running as a Docker container.

Triton exposes HTTP (REST), gRPC, and Prometheus endpoints.  The test client [`test_triton_client.py`](test_triton_client.py) exercises the same four sample sequences and live-scoring example as the Jupyter notebook [`APP_Fraud_LSTM_model_serving.py`](../zST-model-serving-jupyter/APP_Fraud_LSTM_model_serving.py).

## Step-by-step

### 1 · Set up the model repository

```bash
python3 serve.py
# optional flags:
#   --model-path /path/to/fraud_detection_unified.onnx
#   --repo-dir   /path/to/model_repository
```

`serve.py` copies the ONNX file and writes `config.pbtxt` — it only needs to run once (or whenever the model changes).

### 2 · Build the Docker image

```bash
# IBM z16 / LinuxONE (default):
docker build -t triton-fraud-detection .

# x86_64 development machine:
docker build \
  --build-arg BASE_IMAGE=nvcr.io/nvidia/tritonserver:24.01-py3 \
  -t triton-fraud-detection .
```

### 3 · Start the container

```bash
docker run -d \
  --name triton-server \
  -p 8000:8000 \
  -p 8001:8001 \
  -p 8002:8002 \
  -v $(pwd)/model_repository:/models:ro \
  triton-fraud-detection
```

### 4 · Run the tests

Install client dependencies into your Python / virtual environment (quotes around `"tritonclient[http]"` are required in shells like `zsh` to prevent glob expansion):

```bash
# Activate virtual environment if applicable
source ../.venv/bin/activate

# Install client packages
pip install "tritonclient[http]" numpy

# Execute tests
python3 test_triton_client.py [--url localhost:8000]
```

> **Tip:** If your global `pip` configuration enforces `--user` installs, install inside a virtual environment using:
> ```bash
> pip install --no-user "tritonclient[http]" numpy
> ```

## Endpoints

| Port | Protocol | Purpose |
|------|----------|---------|
| 8000 | HTTP/REST | Inference (`POST /v2/models/{model}/infer`), health, metadata |
| 8001 | gRPC | Inference (gRPC protocol) |
| 8002 | HTTP | Prometheus metrics (`/metrics`) |

### Example: raw HTTP inference call

```bash
# Health check
curl http://localhost:8000/v2/health/ready

# Model metadata
curl http://localhost:8000/v2/models/fraud_detection

# Metrics
curl http://localhost:8002/metrics
```

## Model inputs / outputs

The model accepts **24 named inputs**, one tensor per feature, each shaped `[batch, 7, 1]`.

| Tensor | dtype | Shape | Description |
|--------|-------|-------|-------------|
| `month` … `from_bank_num_total_locations` (15 inputs) | FP32 | `[batch, 7, 1]` | Numeric features |
| `from_entity_type` … `payment_currency` (9 inputs) | BYTES (string) | `[batch, 7, 1]` | Categorical features |
| **`Identity:0`** | FP32 | `[batch, 7, 1]` | Per-timestep fraud probability |

The **peak** fraud probability across all 7 timesteps is used as the fraud score: `output[:, :, 0].max(axis=1)`.
Classification threshold: **0.5**.

## Test suite summary

| Test | Description |
|------|-------------|
| 1 · Server health | Asserts `is_server_live`, `is_server_ready`, `is_model_ready` |
| 2 · Genuine sequences | G-1 (checking), G-2 (money market) — expects score < 0.5 |
| 3 · Fraud sequences | F-1…F-4 (real APP fraud from CSV, 4 fraudsters) — expects score ≥ 0.5 |
| 4 · Timestep evolution | Prints per-timestep probabilities for all 6 sequences |
| 5 · Summary table | Accuracy across 6 labelled sequences |
| 6 · Live scoring | Suspicious late-night Wire appended to genuine G-1 history |
| 7 · Throughput benchmark | 1 000-sequence timed batch |

## IBM z16 / LinuxONE — Telum AIU notes

The default base image (`icr.io/ibmz/ibmz-accelerated-for-nvidia-triton-inference-server`) targets **IBM z16 / LinuxONE**.  
On these platforms the ONNX Runtime backend can be configured to route compatible operators to the on-chip **Telum AI Unit (AIU)** via the [IBM ONNX Runtime Telum EP](https://github.com/IBM/onnxruntime-ep-telum).

To enable the Telum EP, add an `optimization` block to `config.pbtxt` after running `serve.py`:

```protobuf
optimization {
  execution_accelerators {
    cpu_execution_accelerator [
      {
        name: "telum"
      }
    ]
  }
}
```

For x86_64 development, override the base image:

```bash
docker build \
  --build-arg BASE_IMAGE=nvcr.io/nvidia/tritonserver:24.01-py3 \
  -t triton-fraud-detection .
```
